# Roadmap v1.4.0 — Enriched Transactions

> **Status:** Planned  
> **Target branch:** `backend` + `frontend`  
> **Previous version:** v1.3.0  
> **Dependencies:** v1.3.0 must be complete (React working)

---

## Goal

Enrich the transaction model with store, subcategory, who paid, who was paid,
and a purchase item breakdown — turning each transaction into a complete,
analyzable receipt.

---

## Database Changes

### New table: `stores`

| Column     | Type           | Notes                                      |
|------------|----------------|--------------------------------------------|
| id         | UUID PK        |                                            |
| name       | VARCHAR(120)   | NOT NULL                                   |
| category   | VARCHAR(80)    | e.g. supermarket, pharmacy, restaurant     |
| address    | VARCHAR(200)   | NULLABLE                                   |
| created_at | TIMESTAMP      |                                            |
| updated_at | TIMESTAMP      |                                            |

### New table: `subcategories`

| Column      | Type         | Notes                          |
|-------------|--------------|--------------------------------|
| id          | UUID PK      |                                |
| name        | VARCHAR(80)  | NOT NULL                       |
| category_id | FK           | references categories.id       |
| created_at  | TIMESTAMP    |                                |

### New table: `transaction_items`

| Column         | Type           | Notes                                      |
|----------------|----------------|--------------------------------------------|
| id             | UUID PK        |                                            |
| transaction_id | FK             | references transactions.id ON DELETE CASCADE |
| name           | VARCHAR(150)   | NOT NULL                                   |
| quantity       | DECIMAL(10,2)  | DEFAULT 1                                  |
| unit_price     | DECIMAL(12,2)  | NOT NULL                                   |
| subtotal       | DECIMAL(12,2)  | quantity * unit_price (computed in service) |
| notes          | TEXT           | NULLABLE                                   |

### Changes to `transactions` table

| New column        | Type        | Notes                                          |
|-------------------|-------------|------------------------------------------------|
| store_id          | FK NULLABLE | references stores.id                           |
| subcategory_id    | FK NULLABLE | references subcategories.id                    |
| paid_by           | FK NULLABLE | references users.id                            |
| paid_to_user_id   | FK NULLABLE | references users.id (mutually exclusive below) |
| paid_to_store_id  | FK NULLABLE | references stores.id (mutually exclusive above)|
| has_items         | BOOLEAN     | DEFAULT FALSE                                  |

> **Note:** `paid_to` is polymorphic. Two nullable FK columns are used
> (`paid_to_user_id`, `paid_to_store_id`) to maintain referential integrity.
> Only one can have a value at a time — enforced at the service layer.

## Backend

### New endpoints

| Method | Route                                    | Description               |
|--------|------------------------------------------|---------------------------|
| GET    | `/stores`                                | List stores               |
| POST   | `/stores`                                | Create store              |
| GET    | `/stores/{id}`                           | Store detail              |
| PATCH  | `/stores/{id}`                           | Update store              |
| GET    | `/subcategories`                         | List subcategories        |
| POST   | `/subcategories`                         | Create subcategory        |
| GET    | `/transactions/{id}/items`               | List items of transaction |
| POST   | `/transactions/{id}/items`               | Add item                  |
| PATCH  | `/transactions/{id}/items/{item_id}`     | Edit item                 |
| DELETE | `/transactions/{id}/items/{item_id}`     | Delete item               |

### Changes to existing endpoints

- `GET /transactions/{id}` → include `store`, `subcategory`, `paid_by`, `paid_to`, `items[]`
- `POST /transactions` → accept new optional fields
- `PATCH /transactions/{id}` → allow updating new fields

## Frontend (React)

### `/transactions/:id` — Transaction Detail
- Full info: amount, date, category, subcategory, store
- "Who paid" section with user avatar
- "Paid to" section with store or person name
- Items table with quantity, unit price, subtotal
- Inline add/edit item button

### New Transaction Form — enhancements
- Store selector (with inline create option)
- Subcategory selector filtered by category
- "Paid by" field → user dropdown
- "Paid to" field → toggle: Store / Person
- Collapsible "Purchase breakdown" section with editable items table

### Catalog Management
- `/stores` — Stores CRUD
- `/subcategories` — Subcategories CRUD

## Acceptance Criteria

- [ ] A transaction can be created with store, subcategory and payer
- [ ] A transaction can be opened and its items viewed and edited
- [ ] Transaction total matches the sum of its items (when items exist)
- [ ] Transaction filters work with subcategory and store
- [ ] Home dashboard reports reflect subcategory data
- [ ] Alembic migrations run cleanly on Railway without data loss
- [ ] `paid_to_user_id` and `paid_to_store_id` are mutually exclusive (service validation)

## Technical Notes

- `subtotal` in `transaction_items` is computed in the service layer, not as a generated column.
- Mutual exclusivity of `paid_to_user_id` and `paid_to_store_id` must be validated at the service layer.
- Items are optional. `has_items = True` only when at least one item is recorded.
- Add database indexes on `transactions.store_id` and `transactions.subcategory_id` for reporting queries.
